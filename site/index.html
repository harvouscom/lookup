01

Stop retyping church details

Church tools keep asking people for the same details. Lookup fills them in from Here's My Church, an open directory of 587,842 churches in 19 countries.

  • Search as you typePrefixes, typos and places like "church in dallas" all work, nearby churches first.
  • Fill your formPick a church and empty fields fill in. Anything already typed is left alone.
  • Share fixes backCorrections made in your app flow back to the directory. Coming next.

02

Quickstart

Add the script, put <church-lookup> in your form, and mark the fields it should fill with data-hmc-field. There's no key to request.

<form>
  <church-lookup label="Your church"></church-lookup>
  <input name="street"  data-hmc-field="street">
  <input name="city"    data-hmc-field="city">
  <input name="website" data-hmc-field="website">
</form>
<script type="module" src="https://lookup.heresmychurch.com/element.js"></script>
import { createLookup } from "https://lookup.heresmychurch.com/lookup.js";

const lookup = createLookup({ client: "my-app" });
const { results } = await lookup.search("grace comm");
const church = await lookup.getChurch(results[0].id);
# Coming soon. The package isn't published yet.
npm install @heresmychurch/lookup

Try it in a real form. Values are set the way typing sets them, so React and other frameworks see them.

03

The widget

<church-lookup> is an accessible combobox. It searches as people type, asks for smarter results when they pause, and fills your form when they choose.

Attributes

label, placeholder
The visible label and the hint inside the box.
region, country
Limit results, such as region="TX" or country="DE".
near
Rank results near a place, such as near="Dallas".
geo="off"
Don't use the visitor's approximate location.
form
The id of the form to fill. Defaults to the enclosing form.
overwrite
Replace fields that already have values.
limit
How many results to show, up to 20. Defaults to 8.

Fields

Use any of these in data-hmc-field: name, street, city, region, regionName, postalCode, country, countryName, latitude, longitude, phone, email, website, denomination, serviceTimes, languages, ministries, pastorName and id.

Events

church-results
Results appeared. detail has query, results and settled.
church-select
A church was chosen. Cancel it to stop the fill.
church-fill
Fields are about to fill. Cancel it to fill them yourself from detail.record.

An ARIA 1.2 combobox: arrow keys move through results, Enter chooses and Escape closes. Results and fills are announced, targets are 44 pixels, and it respects forced colors and reduced motion.

04

Service times

Wrap a service-times field in <church-service-times> to edit it as rows of day, time and label, the same way Here's My Church does. The field keeps one plain string, such as Sun 9:00 AM (Main Service); Wed 7:00 PM, so it submits like any input.

html
<church-service-times>
  <textarea name="times" data-hmc-field="serviceTimes"></textarea>
</church-service-times>
<script type="module" src="https://lookup.heresmychurch.com/service-times.js"></script>

06

API

Base URL https://lookup.heresmychurch.com/v1. Open CORS, no key, no cookies.

GET /v1/search

send a request to the live api
{}
q
What the person typed. Place words like "in Dallas" or ", TX" are understood.
near, lat, lng
Rank near a place or point.
country, region
Only return churches there.
limit
1 to 20. Defaults to 8.
settled=1
The person paused, so semantic search may run.
geo=off
Don't use the request's approximate location.

GET /v1/churches/:id

The autofill record. Every key in fields is always present, with null or [] when empty, plus missing, completeness and hints.

GET /v1/meta

Field names, what can be contributed and how it's reviewed, completeness weights, counts and attribution.

120 searches and 30 semantic searches a minute per visitor. Over the limit returns 429, a busy database returns 503, and both send Retry-After.

07

How search works

  1. Words, as you type. A full-text index finds names that start with what's typed: nearby first, then wider, then the whole country.
  2. Places. "church in dallas", "grace, chicago" and "first baptist TX" become a place filter. A lowercase "in" is never read as Indiana.
  3. Spelling. When almost nothing matches, the closest spelling is tried, so "gracee" finds Grace.
  4. Meaning, only when words fail. If no result matches every word, a settled query also asks semantic search (bge-m3 in Cloudflare Vectorize). Those results always rank below real name matches.

78 held-out test queries we didn't tune on, against Here's My Church's search today:

Semantic search helped two queries in 78 and hurt none. It doesn't fix translations such as "trinity church munich", and common names with no location stay hard. Full write-up.

08

Data and review

Lookup reads Here's My Church's reviewed listings and re-syncs changed regions every 5 minutes. Searches aren't logged, and approximate location is only used in memory to rank nearby churches.
